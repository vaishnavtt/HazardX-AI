# Phase 36 — Frontend-Backend Integration and Consistency Report

## 1. Executive Summary

This report validates that the React/TypeScript frontend (`http://localhost:5173`) accurately reflects the calibrated, scientifically defensible risk outputs generated by the FastAPI backend (`http://127.0.0.1:8000`).

Previously, the frontend rendered raw uncalibrated probabilities directly as integer percentages (e.g., converting an uncalibrated $0.09$ into "Estimated Threat Score: 9%"), and defaulted undefined/zero scores to $10\%$, creating false user perceptions of risk during benign conditions.

---

## 2. Frontend Contract Improvements

### 2.1 Calibrated Probability Mapping in `LocationAssessmentPage.tsx`
- **Field Binding:** The UI now inspects `hData.calibrated_probability` (falling back to `hData.probability` only if calibrated score is unavailable).
- **Zero & Precision Handling:**
  - $p = 0.0 \implies \mathbf{0.0\%}$ (never defaults to $10\%$).
  - $p < 0.001 \implies \mathbf{< 0.1\%}$.
  - $p < 0.01 \implies$ formatted to 1 decimal place (e.g. $0.3\%$).
  - $p \ge 0.01 \implies$ standard percentage integer.
- **Physical Guidance Integration:** Displays `hData.guidance` directly inside the hazard card so users understand the rationale behind the assessment.
- **Defined Target Context:** Renders `hData.defined_target` (e.g. "River Inundation & Reach Overflow (24h horizon)").
- **Data Freshness & Provenance:** Displays live source attribution and real-time pulse indicators (`LIVE`, `Copernicus GloFAS`, `USGS ComCat`, `NASA FIRMS`).
